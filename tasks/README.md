# Tasks workspace
This directory is the umbrella planning layer for weekly delivery execution.

## Structure
- `backlog.md` — prioritized candidate work items.
- `sprint-template.md` — template for weekly sprint planning and review.
- `sprints/` — active and historical sprint files.

## Operating model
- Sprint cadence: weekly.
- Lifecycle: `Backlog -> Ready -> In Progress -> Review -> Validated -> Done`.
- Keep entries concise, verifiable, and mapped to repository artifacts.

## Usage guidance
1. Promote items from `backlog.md` into a new sprint file.
2. Ensure each sprint item has validation criteria.
3. After execution, record outcomes and carry-over explicitly.
