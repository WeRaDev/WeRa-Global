# Sprint 2026-16
## Sprint goal
Realign KB upgrade execution to one canonical `KnowledgeBase/` repository model with domain folders, human-facing wiki readiness, and agent-readiness metadata contracts.
## Scope
In scope:
- lock canonical source of truth to `KnowledgeBase/` in umbrella repository,
- partition domains as folders under `KnowledgeBase/` (not separate canonical repositories),
- freeze existing split `kb-*` repositories as migration staging/history,
- define and sequence canonical consolidation tasks,
- prepare wiki information architecture for human navigation and governed operations,
- prepare structured markdown + metadata contract for later TRL4-TRL5 automation validation (`KB + mempalace + openfang`).
Out of scope:
- production deployment of autonomous mempalace/openfang write automation,
- full Nextcloud synchronization implementation (contract/design only in this sprint),
- deletion of split repositories (freeze policy only).

## Risks and dependencies
- Risk: dual-source confusion between canonical KB and split staging repos.
  - Mitigation: explicit freeze policy and canonical-path-only authoring rule.
- Risk: consolidation drift and metadata inconsistency.
  - Mitigation: provenance-preserving consolidation index and chain validation checks.
- Risk: governance ambiguity during transition.
  - Mitigation: mandatory `temporal_scope` metadata + three-entity routing.
- Dependency: governance council approval of single-repo architecture lock.
